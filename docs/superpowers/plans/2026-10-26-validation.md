# Проверка LDAP и доступа по клиентам

Репозиторий: `/Users/kirillkolomoec/Documents/api-main`, ветка `feature/ldap-access`.

## Что проверяется

- Первый доменный вход создаёт одну учётную запись без ролей; повторный вход сохраняет идентичность и назначенные роли.
- Отключение, удаление и исключение из разрешённого фильтра каталога блокируют доступ. Ошибка LDAP не приводит к частичной массовой деактивации. Ручная блокировка сохраняется.
- TLS проверяет CA и имя узла; пароль bind не возвращается в API, хранится в зашифрованном виде.
- Роли объединяют коды источника/получателя; DWH не совпадает с DWH-TEST. Пустая область не открывает данные. ADMIN видит все данные.
- Ограничения действуют до пагинации, на прямых идентификаторах, сессиях, файлах, операциях запуска/остановки и расписаниях. Дополнительный RLS применяется с пересечением.
- Пользователь без прав видит описание панели. Настройки доступны только ADMIN, включая переход по прямому адресу.

## Независимое ревью

Исправлены выявленные проблемы LDAP: применение userFilter при синхронизации и пакетный поиск по постоянным идентификаторам через одно TLS-соединение. Найденная гонка контекста при смене пользователя также включена в регрессионную проверку интерфейса.

## Известные границы проверки

Корпоративный AD не подключён: адрес, служебные реквизиты и CA пока не предоставлены. Протокольные проверки выполняются с настоящим LDAP SDK и встроенным TLS-каталогом, проверки сохранения — с тестовой БД. На стенде исполнитель является согласованной заглушкой, реальные файлы не передаются.

Общая проверка типов UI выявляет 18 ранее существовавших ошибок, не относящихся к новой функциональности; производственная сборка использует Vite и проверяется отдельно. Синхронизация ограничена 20 секундами сбора и 10 000 зарегистрированных доменных пользователей, изменения применяются только после полного успешного сбора.
