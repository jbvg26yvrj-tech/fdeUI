# Аналитика и внешние Loki

Аналитика читает существующие таблицы `sessions.pipeline_sessions`, `sessions.task_sessions`, `sessions.processed_files`. Новые запуски для заполнения графиков не требуются.

## Время и тестовый стенд

`ANALYTICS_SOURCE_TIME_ZONE` задаёт IANA-зону значений timestamp без смещения в БД. На этом стенде подтверждён UTC: PostgreSQL использует Etc/UTC, исполнитель пишет NOW(). При переносе в другую среду нужно проверить зону писателя, а не только браузера.

`ANALYTICS_TEST_STAND=true` включает пояснение о тестовой среде. Отсутствие processed_files на стенде с заглушкой — реальное отсутствие записей, поэтому графики объёма пустые/нулевые. Это не подтверждение работы передачи файлов.

## Разрешённые серверы Loki

`FDE_LOKI_ALLOWED_HOSTS` — список точных имён хостов и портов через запятую, например `loki-sp.example.internal:443,loki-sc.example.internal:8443`. Хост без порта означает 443. Подстановочные знаки не поддерживаются. Пустой список позволяет сохранить форму подключения, но запрещает тесты и запросы к внешним адресам.

Для стенда изменение выполняется администратором инфраструктуры после получения реальных адресов:

```sh
minikube -p fde kubectl -- -n fde set env deployment/fde-api \
  FDE_LOKI_ALLOWED_HOSTS=loki-sp.example.internal:443,loki-sc.example.internal:8443
```

Примерные адреса требуется заменить реальными. URL должен использовать HTTPS; корпоративный CA добавляется в доверенные сертификаты Java. Не отключать проверку TLS для устранения ошибки сертификата.

## Секрет подключения

`FDE_LOKI_ENCRYPTION_KEY` — независимый от LDAP ключ AES-GCM, 32 случайных байта в Base64. На стенде передаётся через Kubernetes Secret `fde-loki`, исходный файл `/home/fdeadmin/fde/deploy-20261026/loki-secret.env` доступен только владельцу (0600). Ключ не печатать и не коммитить. Его нужно резервировать отдельно от дампа БД: без него зашифрованные пароли и токены не восстановятся. Простая замена ключа не является ротацией — старые значения сначала нужно расшифровать и перешифровать управляемой процедурой.

В админке: Настройки → Loki → добавить подключение; указать название, URL, авторизацию и tenant при необходимости, базовые метки и имена полей корреляции. «Проверить» проверяет read API, не сохраняет форму. Пустой ответ означает доступный источник без подходящих строк.

Секрет в форме не заполняется обратно. Пустое поле при редактировании сохраняет прежнее значение; очистка явная. Отключённый источник не участвует в поиске.

## Права и сопоставление логов

Новые функциональные права: `page.analytics`, `api.analytics.read`, `page.logs`, `api.logs.read`. Новые права не выдаются всем доменным пользователям автоматически. ADMIN доступен весь раздел; остальные ограничены назначенными правами и существующей областью клиентов/RLS.

Обычный пользователь ищет логи конкретной доступной сессии. Логи должны содержать точный sessionId в указанном JSON-поле либо structured metadata. Если корреляции нет, это нужно исправить в настройках источника/формате логов; нельзя заменять запрос общими логами. Администратор может читать общие логи в пределах базовых меток подключения.

БД и Loki могут иметь разные сроки хранения. Наличие сессии в аналитике не гарантирует наличия её логов. Сообщение «нет строк» относится только к выбранному окну, а усечение лимитом не означает полноту выдачи.

## Проверка после установки

- Обзор за период существующих сессий совпадает с read-only SQL: COUNT по статусам и отдельные SUM успешных Download/Upload. Не суммировать Download и Upload в один показатель уникальных файлов.
- Пользователь DWH не видит статистику или логи PC→OFD, если у него нет другой разрешающей области.
- Новый источник без доступного хоста не выполняет сетевой запрос; ошибки подключения не показывают токены или тела ответа upstream.
- Реальную интеграцию с корпоративным Loki можно подтвердить только после ввода его адреса, параметров корреляции и действующего доступа.


## Формат structured metadata

Режим METADATA запрашивает `X-Loki-Response-Encoding-Flags: categorize-labels` и проверяет `values[][2].structuredMetadata`. Обычный query-ответ может объединять метаданные с метками потока; эти метки не используются как доказательство принадлежности записи сессии. Если источник не отдаёт раздельные метаданные, строки без точной корреляции не показываются. Режим JSON проверяет поле внутри самой строки лога.

Контракт сверён с [официальным сериализатором Loki](https://github.com/grafana/loki/blob/main/pkg/util/marshal/query.go) и [HTTP API](https://grafana.com/docs/loki/latest/reference/loki-http-api/). Совместимость конкретного внешнего сервера проверяется при его подключении.
